# Стратегический роадмап внедрения Data Mesh

Роадмап привязан к бизнес-целям «Будущего 2.0» и трём этапам трансформации.

## Ключевые роли

| Роль | Ответственность |
|------|-----------------|
| **Data Product Owner (DPO)** | Владелец дата-продукта домена: бэклог, качество, SLA, контракты |
| **Data Engineer** | Пайплайны, потоковые витрины, интеграции, платформенные компоненты |
| **BI-аналитик** | Отчёты и дашборды в self-service BI, требования к дата-продуктам |
| **Platform Team** | Самообслуживаемая платформа (Kafka, каталог, IaC, CI/CD) |
| **Data Governance / CISO** | Политики доступа, комплаенс (152-ФЗ/банк. тайна), безопасность |

## Этапы и привязка к бизнес-целям

### Этап 1. Пилот (0–6 мес)
**Бизнес-цель (промежуточная):** согласованное архитектурное решение, определённые
границы доменов, конкретные проекты по витрине данных.
- Развернуть event backbone (Kafka), Schema Registry, DLQ.
- Пилот в 1–2 доменах (финансовые расчёты / пациентский поток).
- Ввести роль **DPO**, единые принципы работы с событиями, каталог схем.
- Обучение команд (Kafka, DDD, Data Mesh).

### Этап 2. Масштабирование (6–18 мес)
**Бизнес-цель (финальная, ~год):** реализован портал самообслуживания;
бизнес-пользователи работают с данными в новой архитектуре; legacy временно в
отдельных доменах.
- Anti-Corruption Layer к DWH/Camel (CDC через Debezium).
- Потоковые витрины (Flink + ClickHouse), запуск **Self-Service BI**.
- Расширение на критические домены.
- Data Governance (доступы, комплаенс) + FinOps (контроль затрат).

### Этап 3. Отказ от legacy (18–36 мес)
**Бизнес-цель (долгосрочная, 3 года):** слабосвязанная событийная платформа;
масштабирование по продуктам, географии, данным; переход к near-real-time.
- Вывод точечных синхронных интеграций (strangler-паттерн).
- Доменная аналитика на потоках (near-real-time).
- Вывод DWH SQL Server 2008 и PowerBuilder.
- Подключение новых направлений (фарма, электроника) через события.

## Метрики успеха

| Метрика | Базовое (as-is) | Цель (3 года) |
|---------|-----------------|---------------|
| Время построения сложного отчёта | часы | секунды–минуты |
| Time-to-market нового дата-продукта | месяцы | недели |
| Кол-во дата-продуктов в каталоге | 0 | 30+ |
| Доля near-real-time потоков | ~0% | 60%+ |
| Подключение нового домена | месяцы, правки DWH | дни, подписка на топик |
| TCO (3-летний) | ~749 млн ₽ | ~528 млн ₽ (−30%) |
