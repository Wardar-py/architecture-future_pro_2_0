# Агрегаты доменов

Описание ключевых агрегатов: корень агрегата, границы консистентности, инварианты и идентификаторы.

## Patient Flow

### Patient
- **Корень:** `Patient`
- **Ключ:** `patient_id` (UUID)
- **Границы:** персональные данные пациента, контакты, согласия.
- **Инварианты:**
  - Пациент уникален по документу/полису (не более одной активной записи).
  - Обработка данных допустима только при наличии согласия (152-ФЗ).
- **Не входит:** содержимое ЭМК (отдельный защищённый контур).

### Encounter
- **Корень:** `Encounter`
- **Ключ:** `encounter_id`, ссылка на `patient_id`
- **Инварианты:**
  - Приём привязан к существующему пациенту и врачу.
  - Нельзя завершить приём без зафиксированного статуса.

## AI Diagnostics

### Study
- **Корень:** `Study`
- **Ключ:** `study_id`, ссылка на `encounter_id`
- **Инварианты:**
  - Исследование связано с приёмом.
  - Снимки хранятся в защищённом мед. контуре, не покидают домен.

### AIInference
- **Корень:** `AIInference`
- **Ключ:** `inference_id`, ссылка на `study_id`
- **Инварианты:**
  - Заключение не создаётся без завершённой обработки исследования.
  - Версия модели ИИ фиксируется (аудируемость).

## Lending

### LoanApplication
- **Корень:** `LoanApplication`
- **Ключ:** `application_id`, ссылка на `client_id`
- **Инварианты:**
  - Сумма заявки > 0 и в пределах продуктовых лимитов.
  - Договор создаётся только по одобренной заявке (после скоринга).

### LoanContract
- **Корень:** `LoanContract`
- **Ключ:** `contract_id`, ссылка на `application_id`, `account_id`
- **Инварианты:**
  - Остаток задолженности не может быть отрицательным.
  - График платежей согласован; изменение только через доменную команду.

## Accounts & Payments

### Account
- **Корень:** `Account`
- **Ключ:** `account_id`, ссылка на `client_id`
- **Инварианты:**
  - Баланс не уходит ниже разрешённого лимита (овердрафт по правилам продукта).
  - Валюта счёта неизменна после открытия.

### Transaction
- **Корень:** `Transaction`
- **Ключ:** `transaction_id`, ссылка на `account_id`
- **Инварианты:**
  - Двойная запись: сумма списаний = сумме зачислений.
  - Идемпотентность по `idempotency_key` (защита от дублей).

## Self-Service BI

### DataProduct
- **Корень:** `DataProduct`
- **Ключ:** `data_product_id`, владелец — домен
- **Инварианты:**
  - У дата-продукта есть владелец (Data Product Owner) и схема в каталоге.
  - Публикуемые поля соответствуют уровню доступа (нет мед. содержимого).

### Report
- **Корень:** `Report`
- **Ключ:** `report_id`, ссылка на `user_id`
- **Инварианты:**
  - Отчёт строится только по дата-продуктам в пределах уровня доступа автора.

## Правила проектирования агрегатов

1. **Одна транзакция - один агрегат.** Консистентность между агрегатами через события.
2. **Ссылки между агрегатами по идентификаторам**, не по объектам.
3. **События публикуются через Outbox** после коммита изменения агрегата.
